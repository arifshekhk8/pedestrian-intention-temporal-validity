# Issue 1 — Temporal Leakage Audit: Report

**Verdict: 🔴 LEAKAGE FOUND**

Generated by `01_leakage_audit.py`. Ground truth = PIE per-frame `cross` attribute (values: `not-crossing` / `crossing` / `crossing-irrelevant`), re-parsed from the annotation XML because the original `01_parse_annotations.py` kept only `action` and dropped `cross`.

## Setup

- Sequences audited: **1389** (crossers 570, non-crossers 819)
- Observation window: **16 frames** ending at `anchor_frame`
- Build TTE: **45 frames (sequences/ default)**
- Leakage = ≥1 frame inside the observation window with `cross == "crossing"` (pedestrian already crossing while observed)

## 1. Window leakage

| Group | N | sequences with ≥1 crossing frame in window | % |
|---|---|---|---|
| Crossers (label=1) | 570 | 387 | 67.9% |
| Non-crossers (label=0) | 819 | 0 | 0.0% |
| **All** | 1389 | 387 | 27.9% |

- Crossers with the **entire 16-frame window already crossing** (all frames `crossing`): **369** (64.7% of crossers) — pure detection, not prediction.
- Crossers with a **genuinely clean window** (0 crossing frames): **183** (32.1% of crossers).
- Crossers whose **anchor frame itself** is already `crossing`: **372** (65.3% of crossers)
- Crossers with a labelled crossing onset: 570; of those, onset at/before window end (`anchor−onset ≥ 0`): **521** (91.4%)

- `anchor − onset` (frames): median 182, mean 225.8, min -560, max 6501. Positive ⇒ window reaches into the crossing (leakage); negative ⇒ genuine look-ahead prediction.

See `figures/leakage_window_crossing_frames.png` (the key figure) and `figures/leakage_gap_hist.png`.

## 2. Static-shortcut test (anchor-frame bbox geometry)

Can crosser vs non-crosser be separated by the *static* bounding box at the last observed frame, with no temporal info? Mann–Whitney U (two-sided); rank-biserial |r|: 0=none, 0.1 small, 0.3 medium, 0.5 large.

## 3. Interpretation

- **Window leakage present** in 387/570 crossers (67.9%). For those sequences the model sees the pedestrian already crossing, so a high AUC is partly trivial detection, not prediction. This must be fixed in Issue 2 by anchoring the window strictly *before* crossing onset (event-relative TTE).
- **Static-geometry shortcut:** bbox_bottom_y (r=+0.49), bbox_height (r=+0.63), bbox_area (r=+0.65) separate the classes at the anchor frame on their own. Position/size is a confound; report it and consider position-invariant features (Issue 7) so the model is not just reading screen location.
